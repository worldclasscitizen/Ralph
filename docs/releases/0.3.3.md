# Ralph 0.3.3

[English](https://github.com/worldclasscitizen/Ralph/blob/v0.3.3/README.md) · [한국어](https://github.com/worldclasscitizen/Ralph/blob/v0.3.3/README.ko.md)

Ralph 0.3.3 fixes the publication step against the behaviour that actually blocked 0.3.2. The runtime, execution API, approval rules, catalog and evidence gates are unchanged.

- The registry visibility window now covers npm's measured propagation delay: 0.3.1 appeared 2 minutes 13 seconds after its upload and 0.3.2 after 2 minutes 40 seconds, so the workflow waits up to six minutes instead of one.
- npm's own output is forwarded to the workflow log and kept in the failure message. It used to be discarded, which made a failed upload look identical to a slow registry.
- The upload is never repeated. npm rejects a second upload of the same version, so retrying the publish would only obscure the real state; the registry is re-read instead.
- Every registry read carries an explicit abort signal, because Node's global `fetch` has no documented request deadline, and a read that times out is retried like a missing version. A version that exists with a different artifact still stops the workflow immediately.

## Release history note

`0.3.2` exists on npm but never received a public GitHub Release. Its evidence gate, tag and draft release all succeeded; the publish step then stopped after a sixty-second visibility window even though npm had accepted the upload, and the artifact only became visible about three minutes later. Because a published npm version is immutable, the documentation and test changes made afterwards cannot be republished as `0.3.2`, so this patch release supersedes it. The `v0.3.2` tag remains on the commit that produced the published artifact.

Install with npm install -g @worldclasscitizen/ralph@0.3.3. Node.js 22 or 24 and Git are required.

## Verification scope for 0.3.3

Provider and functional gates passed on a real Codex session: four transport checks with `codex-cli 0.155.1` and `gpt-6-sol`, then a generated four-node graph completed in eight model calls and 272549 wall-clock milliseconds through starting-branch delivery, with two isolated scoped workers, independent reviews, integration, final validation and an external oracle. The recorded environment is Windows and Node.js 24.11.1; the ledger for this release started fresh after the retained 0.3.2 ledger was archived beside it, and consumed 12 calls and 292782 of the 1800000 active-millisecond ceiling.

Every other candidate, including `gemini-3.8-flash` and all API transports, remains protocol-tested only. Publication still requires the six-cell CI matrix on the exact merged commit. See [release readiness](../project/v0.3-readiness.md) and the [0.3.3 local verification record](../project/local-verification-0.3.3.json).

## 한국어 변경 사항

0.3.3은 0.3.2를 막았던 실제 원인에 맞춰 게시 단계를 고칩니다. 런타임, 실행 API, 승인 규칙, 카탈로그, 증거 게이트는 그대로입니다.

- 레지스트리 가시성 대기 창이 실측된 npm 반영 지연을 덮습니다. 0.3.1은 업로드 후 2분 13초, 0.3.2는 2분 40초 뒤에 나타났고, 이제 최대 6분을 기다립니다.
- npm 출력을 워크플로 로그와 실패 메시지에 남깁니다. 이전에는 버려서, 업로드 실패와 느린 레지스트리를 구분할 수 없었습니다.
- 같은 버전을 두 번 업로드하지 않습니다. npm이 동일 버전 재업로드를 거부하므로 게시를 재시도하면 실제 상태만 흐려집니다. 대신 레지스트리를 다시 읽습니다.
- 모든 레지스트리 조회에 명시적 중단 신호를 걸었고(Node 전역 `fetch`에는 문서화된 요청 기한이 없습니다), 시간 초과 조회는 없는 버전처럼 재시도합니다. 바이트가 다른 같은 버전이 있으면 즉시 중단합니다.

0.3.2는 npm에는 올라갔지만 GitHub 공개 릴리스는 없습니다. 증거 게이트·태그·초안 릴리스는 모두 성공했고, npm이 업로드를 받아들인 뒤에도 60초 대기 창이 먼저 끝나 실패했습니다. 실제로는 약 3분 뒤에 반영되었습니다. 게시된 npm 버전은 불변이므로 이후의 문서·테스트 변경을 0.3.2로 다시 올릴 수 없어, 이 패치가 이를 대체합니다. `v0.3.2` 태그는 게시된 아티팩트를 만든 커밋에 그대로 남아 있습니다.

0.3.3도 실제 Codex 세션으로 공급자·기능 게이트를 통과했습니다(`codex-cli 0.155.1`·`gpt-6-sol`, 4개 전송 검사, 8회 호출·272549ms로 4노드 그래프를 시작 브랜치까지 반영). 원장은 0.3.2 원장을 보존한 뒤 새로 시작해 12회 호출·292782ms(상한 1800000ms)를 사용했습니다. 나머지 후보 모델은 여전히 프로토콜 모의 검증 단계입니다.
