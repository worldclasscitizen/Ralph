# Ralph 0.3.1

[English](https://github.com/worldclasscitizen/Ralph/blob/v0.3.1/README.md) · [한국어](https://github.com/worldclasscitizen/Ralph/blob/v0.3.1/README.ko.md)

Ralph 0.3.1 refreshes the signed model catalog and makes provider onboarding a guided command. The execution API, approval rules and evidence gates are unchanged from 0.3.0.

## Provider setup

`ralph auth setup` is the new entry point: it prints every provider with its current state, asks which providers to connect, offers only the transports that provider actually supports (an installed CLI login or an API key), reads the API key without echoing it, and lets you tick any number of models per connection. Running it with no arguments changes nothing until you answer; a non-terminal stdin fails immediately instead of hanging, and scripted hosts use `--provider`, `--method`, `--key-stdin`/`--key-env` and `--models`. Codex, Claude Code, Gemini CLI and Antigravity all invoke this same CLI, so the flow is identical everywhere.

- API keys go to the macOS Keychain or the Freedesktop Secret Service when present; otherwise to a per-user `credentials.json` with owner-only permissions, outside every repository, encrypted with Windows DPAPI where available. `RALPH_CREDENTIAL_STORE=file` and `RALPH_CREDENTIAL_ENCRYPTION=none` override those choices, and `ralph auth status` reports both the location and whether the secret is protected.
- A transport that cannot report its login state (Gemini CLI, Antigravity) counts as connected only after the operator confirms it, recorded as `trusted` on that connection; non-interactive runs must pass `--assume-login`. Installation alone never enables a route.
- The chosen models are stored per connection and are no longer widened by later discovery during `ralph init`.
- Route rebuilding now also triggers when a model selection changes, not only when authentication changes.
- The catalog cache is consulted only when it is strictly newer than the bundled catalog. An equal version previously let a stale cached file shadow the rebuilt bundled one, which could make routing and `npm run catalog:audit` disagree with the shipped artifact.
- Model choices are documented with their reasons in [Providers](../providers/index.md).

## Model catalog

Catalog version 6 (checked 2026-09-27, expires 2027-03-27) is re-signed with the existing Ed25519 trust anchor; the key id is unchanged. A cached catalog is now used only when it is strictly newer than the bundled one, so a stale local cache can no longer shadow the artifact shipped with the package.

- Only the newest model of each tier is listed: gpt-6-astra, gpt-6-sol, gpt-6-luna, claude-opus-5-5, claude-fable-5-1, gemini-3.8-flash, deepseek-flash and glm-5.3 / glm-5.3-flash, across the nine configured adapters (17 entries).
- `claude-haiku-4-5` is removed. It is the only current Claude limited to 200K context, and the credible criticism against it concerns autonomous coding-agent work — this project's workload. No low-cost Claude is offered, by decision.
- `deepseek-v4-pro` is removed because DeepSeek rerouted that id to `deepseek-flash` on 2026-09-14; it no longer names a distinct model.
- Superseded ids (`gpt-5.6-*`, `gpt-5.4-mini`, `claude-sonnet-5`, `gemini-2.5-flash`, `gemini-3.7-flash`, `glm-5`) are deleted rather than kept as silent fallbacks.
- The Z.ai coding-plan entry now names the adapter the runtime actually configures (`zai-coding-plan`). It previously named `zai-coding-api`, which no connection could match, so that plan silently had no candidate models.
- Every entry stays `qualityTier: "unrated"` with null scores and one official evidence page. No quality, speed or cost ranking is invented.

Install with npm install -g @worldclasscitizen/ralph@0.3.1. Node.js 22 or 24 and Git are required.

## Verification scope for 0.3.1

No live provider run was performed for this release and none is claimed. The 0.3.0 certificate records `codex-cli 0.153.4` with `gpt-5.6-luna`, and that model is no longer in the catalog, so no entry in the 0.3.1 routing pool has live support evidence. Provider support stays `compatible` (protocol-level mock coverage) until a conformance and end-to-end run records the model actually used. The digests of the 0.3.0 certificates do not match this tree, so the release gate refuses to reuse them and a fresh CI matrix plus a new live campaign are required before publication. See [release readiness](../project/v0.3-readiness.md) and the [0.3.1 local verification record](../project/local-verification-0.3.1.json).

## 한국어 변경 사항

0.3.1은 서명된 모델 카탈로그를 갱신하고 공급자 연동을 대화형 명령으로 만든 패치입니다. 실행 API, 승인 규칙, 증거 게이트는 0.3.0과 같습니다.

- `ralph auth setup` 하나로 연동 상태 확인 → 공급자 선택 → 로그인/API 방식 선택 → API 키 입력(화면에 표시되지 않음) → 모델 복수 선택까지 진행합니다. 인자가 없으면 응답하기 전까지 설정을 바꾸지 않고, 터미널이 아니면 멈추지 않고 즉시 실패합니다. Codex·Claude Code·Gemini CLI·Antigravity는 모두 같은 CLI를 호출하므로 어디서든 동일하게 동작합니다.
- API 키는 macOS 키체인 또는 Freedesktop Secret Service가 있으면 거기에, 없으면 저장소 밖 사용자 디렉터리의 `credentials.json`(소유자 전용 권한)에 보관합니다. `RALPH_CREDENTIAL_STORE=file`로 키체인을 건너뛸 수 있습니다.
- 선택한 모델은 연결별로 저장되며, 이후 `ralph init`의 자동 감지가 선택 범위를 넓히지 않습니다.
- 카탈로그 버전 4(2026-09-27 확인, 2027-03-27 만료)를 기존 Ed25519 신뢰 앵커로 재서명했습니다. key id는 그대로입니다.
- `claude-haiku-4-5`는 제외했습니다. 현행 Claude 중 유일하게 200K 컨텍스트이고, 신뢰할 만한 비판이 자율 코딩 에이전트 작업—즉 이 프로젝트의 작업—에 집중되어 있습니다. `deepseek-v4-pro`는 DeepSeek이 2026-09-14에 해당 ID를 `deepseek-flash`로 돌렸기 때문에 제외했습니다.
- Z.ai 코딩 플랜 항목의 어댑터 이름을 런타임이 실제로 설정하는 `zai-coding-plan`으로 고쳤고, 같은 플랜에 `glm-5.3-flash`도 추가했습니다. 이전 어댑터 이름(`zai-coding-api`)은 어떤 연결과도 맞지 않아 후보 모델이 비어 있었습니다.
- API 키는 macOS 키체인/Secret Service가 있으면 거기에, 없으면 저장소 밖 사용자 디렉터리 파일에 보관하며 Windows에서는 DPAPI로 암호화합니다. 로그인 상태를 확인할 수 없는 CLI(Gemini, Antigravity)는 사용자가 확인한 경우에만 연결로 인정하고(`trusted`), 비대화형에서는 `--assume-login`이 필요합니다.
- 0.3.1에는 실공급자 검증이 없으며 주장하지 않습니다. 0.3.0 증명서가 기록한 `gpt-5.6-luna`는 카탈로그에 없으므로 현재 후보 풀에는 실제 지원 증거가 있는 모델이 없습니다. 0.3.0 증거는 digest가 달라 재사용이 거부되며, 게시 전에 새 CI와 새 라이브 캠페인이 필요합니다.
