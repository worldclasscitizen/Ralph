> 이 파일은 예시 템플릿입니다. 실제 run 전에 사용자와 대화한 AI가 전체 내용을 구체적으로 작성하고 승인을 받아야 합니다.

한 문장으로 달성할 결과를 작성합니다.

## 프로젝트 기준점

- 프로젝트 루트: `<절대 경로>`

## 배경과 목표

현재 문제, 사용자에게 필요한 결과, 이 작업이 해결해야 할 이유를 작성합니다.

## 작업 범위

- 수정하거나 생성할 기능·파일·문서를 구체적으로 작성합니다.
- 한 run에서 독립적으로 검증할 수 있는 하나의 작업만 둡니다.

## 범위 밖과 금지사항

- 이번 작업에서 변경하지 않을 영역을 작성합니다.
- 기존 사용자 변경, 비밀값, 제어면(`.ralph/**`, `.antigravity/**`, `.git/**`)은 수정하지 않습니다.
- 테스트를 삭제·완화하거나 오류를 숨겨 통과시키지 않습니다.

## 작업 전 확인사항

1. 관련 코드와 기존 테스트를 읽습니다.
2. 현재 실패를 재현하거나 기준 동작을 기록합니다.
3. 실제 프로젝트의 검증 명령과 수정 허용 범위를 확인합니다.

## 구현 요구사항

1. 관찰 가능한 동작과 계약을 작성합니다.
2. 오류·경계 조건과 복구 동작을 작성합니다.
3. 필요한 테스트, 접근성, 보안, 성능 조건을 작성합니다.

## 모델 실행 정책

- 기본적으로 `.antigravity/config.local.json`의 선택 task fallback chain을 사용합니다.
- 시간·비용 제한이 있으면 어떤 단계에서 가벼운 alias를 우선할지 구체적으로 작성합니다.
- 품질이 중요한 판단과 최종 검토는 Worker와 다른 Provider의 Critic을 우선합니다.

## 검증 명령

```bash
.ralph/verify-project.sh
```

프로젝트 고유 명령이 있다면 위 명령이 실제 test·lint·typecheck·build를 실행하도록 연결합니다.

## 완료 증거

- [ ] 요구사항별 구현 파일 또는 문서 경로가 있습니다.
- [ ] 재현 가능한 자동 테스트 또는 결정적 검증 로그가 있습니다.
- [ ] 주요 경계 조건과 오류 처리를 검증했습니다.
- [ ] 관련 없는 변경과 비밀값이 diff에 없습니다.
- [ ] 사용자에게 전달할 결과와 남은 위험을 정리했습니다.
